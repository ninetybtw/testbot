# Астра — эзотерический бот с бесплатным прогнозом

Тестовая механика для заказа «бот по эзотерике на TorroCRM»:

1. Бот в Telegram спрашивает **полное имя**, **дату рождения** и **место рождения**.
2. Данные **записываются в карточку клиента** в CRM, стадия воронки меняется.
3. На основе данных бот выдаёт **бесплатный прогноз**: знак зодиака, восточный гороскоп, число судьбы, число имени, личный год, число места рождения и совет. В конце прогноза бот предлагает полный платный разбор («Хочу полный разбор» → стадия «Хочет полный разбор» и уведомление менеджеру).

Прогноз считается по правилам, а не придумывается: один и тот же человек в течение месяца получает тот же самый текст.

Есть два режима:
- **Самостоятельный бот** — работает уже сейчас, без TorroCRM. Карточки клиентов видны на странице `/crm`, уведомления о лидах приходят вам в Telegram. Этот режим нужен, чтобы показать тест клиенту.
- **Бот на TorroCRM** — когда Torro подключён. Сценарий собирается в конструкторе Torro, а прогноз считает этот же сервер (см. [ниже](#подключение-к-torrocrm)).

## Запуск бота для показа клиенту (≈10 минут, бесплатно)

### 1. Создайте бота в Telegram

1. Откройте [@BotFather](https://t.me/BotFather) → `/newbot`.
2. Введите название, например «Астра — прогнозы», затем имя пользователя, которое заканчивается на `bot`, например `astra_forecast_bot`.
3. BotFather пришлёт **токен** вида `1234567890:AAH…`. Сохраните его.

### 2. Разместите бота на Cloudflare

Понадобится бесплатный аккаунт [Cloudflare](https://dash.cloudflare.com/sign-up). Выберите один из двух способов.

**Способ А — через сайт, без программ**

1. **Storage & Databases → KV → Create** — создайте хранилище с именем `astra-leads`.
2. **Workers & Pages → Create → Start with Hello World → Deploy**. Назовите воркер `astra-bot`.
3. **Edit code**: удалите всё содержимое, вставьте целиком файл [`dist/worker.js`](dist/worker.js) и нажмите **Deploy**.
4. Откройте воркер → **Settings → Bindings → Add → KV namespace**: имя переменной `LEADS`, хранилище `astra-leads`.
5. **Settings → Variables and Secrets → Add**, тип **Secret**:
   - `BOT_TOKEN` — токен от BotFather;
   - `ADMIN_KEY` — придумайте пароль для страницы CRM, например `astra-2026-demo`.

**Способ Б — из командной строки** (нужен Node.js)

```bash
npx wrangler login
npx wrangler deploy                  # хранилище LEADS создастся автоматически
npx wrangler secret put BOT_TOKEN    # вставьте токен от BotFather
npx wrangler secret put ADMIN_KEY    # придумайте пароль для страницы CRM
```

### 3. Подключите бота

Откройте в браузере адрес воркера (его видно в Cloudflare):

```
https://astra-bot.<ваш-ник>.workers.dev/setup?key=<ваш ADMIN_KEY>
```

В ответе будут ссылки на бота и на CRM:

```json
{ "ok": true, "bot": "https://t.me/astra_forecast_bot", "crm": "https://astra-bot.<ник>.workers.dev/crm?key=…", "webhook": "подключён" }
```

Готово: напишите боту `/start`.

### 4. Уведомления о лидах (по желанию)

Напишите боту `/id`, он пришлёт номер вашего чата. Добавьте его в **Settings → Variables and Secrets** как `ADMIN_CHAT_ID` (тип Text) или впишите в `wrangler.toml`. После этого бот будет присылать вам карточку каждого клиента, получившего прогноз, и отдельно отмечать «горячих», которые нажали «Хочу полный разбор».

### Как показать клиенту

- Дайте ссылку на бота: клиент сам пройдёт анкету и получит прогноз.
- Откройте страницу `/crm?key=…` (обновляется каждые 15 секунд) и запишите экран: слева Telegram, справа появляется и заполняется карточка. Показать её вживую можно и на созвоне.
- В боте есть команда `/card` — клиент увидит свою карточку прямо в Telegram.

Ссылку на `/crm` с ключом не публикуйте: на странице персональные данные клиентов. Для боевого запуска понадобятся политика обработки персональных данных и согласие (152-ФЗ).

## Что лежит в папке

| Файл | Что это |
|---|---|
| `src/forecast.js` | Движок прогноза: проверка ввода, зодиак, восточный гороскоп, нумерология, сборка текста |
| `src/telegram.js` | Диалог бота, карточка клиента, уведомления |
| `src/crm.js` | Страница `/crm` со списком карточек |
| `src/worker.js` | Адреса воркера: `/telegram`, `/setup`, `/crm`, `/forecast` |
| `dist/worker.js` | Всё вышеперечисленное одним файлом, для вставки в редактор Cloudflare (`npm run build`) |
| `torro/agent-prompt.md` | Промпты для блока «AI Агент» в TorroCRM |
| `demo.html` | Демо в браузере: чат и карточка CRM |
| `test/` | Автотесты (`npm test`) |

### Как поменять тексты

- Вопросы бота — объект `TEXT` в начале `src/telegram.js`.
- Тексты прогноза — таблицы `SIGNS`, `LIFE_PATH`, `PERSONAL_YEAR`, `PLACE_NUMBER`, `ADVICE` в `src/forecast.js`.
- Предложение платного разбора — переменная `UPSELL_TEXT`, код трогать не нужно.

После правок выполните `npm test` и `npm run build`, затем `npm run deploy` или заново вставьте `dist/worker.js` в Cloudflare.

## Подключение к TorroCRM

Когда TorroCRM подключён, бот работает внутри Torro, а этот сервер только считает прогноз. Самостоятельный режим тогда не нужен: один и тот же бот нельзя подключить и к Torro, и к воркеру.

### Карточка клиента

Подключите бота в Torro: **Каналы → Telegram**, токен от @BotFather. В карточке клиента заведите поля:

| Поле | Формат | Кто заполняет |
|---|---|---|
| ФИО | `Иванова Мария Петровна` | AI-агент |
| Дата рождения | `14.03.1990` | AI-агент |
| Место рождения | `Казань` | AI-агент |
| Знак зодиака | `Рыбы` | AI-агент (вариант Б) или вебхук |
| Число судьбы | `9` | AI-агент (вариант Б) или вебхук |
| Прогноз выдан | `Да` | сценарий |

Стадии воронки: **Новый → Анкета заполнена → Бесплатный прогноз → Хочет полный разбор → Оплачено**.

### Сценарий в конструкторе

```
СТАРТ (клиент нажал /start)
  └─ Отправить сообщение: приветствие + «Как вас зовут полностью — фамилия, имя, отчество?»
  └─ AI Агент (промпт из torro/agent-prompt.md, вариант А или Б)
       заполняет поля «ФИО», «Дата рождения», «Место рождения»
  └─ Условие: все три поля заполнены
       └─ Смена стадии → «Анкета заполнена»
       └─ [Вариант А] Вебхук POST https://astra-bot.<ник>.workers.dev/forecast
            тело: {"name": "{ФИО}", "birth_date": "{Дата рождения}", "birth_place": "{Место рождения}"}
          └─ Отправить сообщение: {forecast из ответа вебхука}
       └─ Смена стадии → «Бесплатный прогноз»
  └─ Условие: клиент написал «полный разбор» → Смена стадии «Хочет полный разбор» + передача менеджеру
```

Публичной документации по API у TorroCRM нет. На сайте сказано, что сценарий можно ветвить по «ответу вебхука». Можно ли вставить поле из ответа в сообщение — нужно проверить в конструкторе.
- Если можно — **вариант А**: точный расчёт на сервере.
- Если нельзя — **вариант Б**: всё делает AI-агент внутри Torro, но в арифметике он может ошибаться.

### Вебхук `/forecast`

```bash
curl -X POST https://astra-bot.<ник>.workers.dev/forecast \
  -H 'Content-Type: application/json' \
  -d '{"name":"Иванова Мария Петровна","birth_date":"14.03.1990","birth_place":"Казань"}'
```

Поля можно называть по-разному: `name` / `full_name` / `fio`, `birth_date` / `dob` / `date`, `birth_place` / `place` / `city`. Подходят JSON, форма и GET-параметры. Чтобы закрыть вебхук от чужих, задайте секрет `API_KEY` и передавайте его в заголовке `X-Api-Key` или параметре `?key=`.

Ответ:

```json
{
  "ok": true,
  "forecast": "🔮 Мария, ваш бесплатный прогноз готов\n\n♓ Знак зодиака: Рыбы ...",
  "full_name": "Иванова Мария Петровна",
  "first_name": "Мария",
  "birth_date": "14.03.1990",
  "birth_place": "Казань",
  "zodiac": "Рыбы",
  "element": "Вода",
  "eastern_year": "Металлическая Лошадь",
  "life_path_number": 9,
  "name_number": 5,
  "soul_number": 5,
  "personal_year": 9,
  "place_number": 5
}
```

Если данные некорректны, вебхук отвечает HTTP 422 и возвращает готовую фразу, которой бот переспросит клиента:

```json
{ "ok": false, "error": "bad_date", "message": "Такой даты не существует. Проверьте день и месяц, например 14.03.1990." }
```

Коды ошибок: `bad_name`, `bad_date`, `bad_place`.
